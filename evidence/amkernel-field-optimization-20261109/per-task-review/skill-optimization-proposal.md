# 通用技能优化方案：保留批量能力，按证据设置反馈边界

## 状态与范围

用户讨论后记录的候选方案，尚未作为已验证规则写入正式 skill。首个证据案例为 BrowserMaze；继续逐项分析原失败，检查规则是否跨案例适用，再决定最小正式修改。不是冻结 campaign 的成绩修订，不改变任务参数、模型、预算、重试上限或 evaluator。

## 原则

鼓励在一次 python_exec 内批量执行。根据交互可靠性、后续动作依赖和状态可观测性设置检查点；能够可靠编程验证的状态尽量在 Python 内检查，只在需要模型判断或发生偏离时返回。

批量能力包括操作、观察、等待、条件判断和停止，不仅是无条件拼接操作。不能把优化退化成所有动作都单独调用模型。

## 批量方式选择

|条件|候选执行方式|
|---|---|
|已验证稳定，后续动作不依赖未知结果|直接批量，保留必要的最终后置条件检查|
|状态可由已有且可靠的文本、属性或其他允许接口判断|脚本内批量，逐阶段验证；偏离即停止依赖它的后续动作|
|状态只有模型看图才能可靠判断|在关键依赖点返回图像和已执行部分，再规划下一批；不要求所有点击都截图|
|交互方式或定位依据尚未验证|先小批试探；确认效果后扩大批量|

## 反馈与停止条件

- 执行前明确预期的可观察业务变化；HTTP 200、无异常、当前 package 正确不能替代业务证据。
- 观察必须能区分目标状态；例如 X 文本仍存在不能证明 X 位置改变。
- 读取成功不代表数据来自本次动作；但合法输出也可能重复，不能把“必须与旧值不同”作为通用完成条件。若允许的观察无法区分旧值与重复的新值，保留歧义，不盲目补发动作或确认进度。
- 检查条件应覆盖阶段分支：出现新内容、进入下一阶段、明确失败或超时。旧控件消失且下一阶段出现，可能是正常进展，不应继续等待旧控件。
- 对稍后会消失的任务信息，保留初始观察及逐阶段证据。批量中途异常后，先检查持久 Python 命名空间中已收集的部分数据；不能用重置列表、猜测缺失值或重新操作代替恢复已有证据。
- 无进展时先区分：尚未完成的异步更新、输入未生效、定位依据变化、对目标/状态理解错误。不盲目重复操作。
- 只有真实存在且可靠的状态读取实现，才能把判断移入脚本；不假定有通用视觉状态解析器。
- 等待应基于足以区分页面阶段的条件，不仅是 package/activity；同一个 activity 可以容纳多个页面。
- 页面布局变化后重新读取定位依据。未经证据，不将 element.click 到坐标 tap 的切换做成通用自动兜底。
- 补发动作前确认前一动作没有迟到生效，避免重复提交或多走一步。
- 返回时保留已完成阶段、最后已确认状态和偏离证据；不把部分执行冒充完成。

## 输入前置条件：确认目标与焦点

输入前确认当前目标是预期的可编辑、可见且启用的控件。确认输入焦点属于该控件；若已有可靠的当前焦点证据，不重复点击。否则用受支持的方式聚焦，并有界等待焦点落在目标字段上；聚焦引起页面/布局变化时重新定位，再输入。不能以键盘出现或某个字段可输入代替目标字段获得焦点的证据。

定位、必要的聚焦、焦点确认、输入、值读回可在一次 Python 调用中串联。焦点未确认则停止依赖该前提的输入/提交；输入异常后先检查当前状态和已有值，不能盲目重复 send_keys。聚焦动作按原协议计入预算，不为省动作而省略必要前提，也不对已经聚焦的控件额外点一次。

这条是用户确认的技能候选要求，尚未写入正式 skill。BrowserMultiply 的原记录显示输入异常后字段 focused=false，但没有观察到聚焦后再次输入的实际结果（被预算 gate 拒绝）；不能认定未聚焦是该异常唯一根因，或宣称这条规则已经修复原任务。

## 文件操作与完成验收：按原始要求核对持久化结果

033 MarkorMergeNotes 暴露的完成检查漏项，属于 AMKernel skills 可改进的指导层范围；不是因为执行代码来自模型，就排除技能优化责任。以下仍是候选建议，尚未修改正式 skill，也未证明模型遵循或成绩提升。

- 创建前区分显示标题、名称字段、独立扩展名字段与完整保存名称；涉及位置要求时同时确认目标目录。应用默认值不是任务要求，隐藏后缀的标题不能证明完整文件名正确。也不能反向将所有未写后缀的笔记名称一律解释为禁止扩展名；以用户要求及允许获得的语义证据为准，无法确定时保留歧义。
- 合并、复制或转录时，默认保留源内容和格式，包括已有换行、空白行及顺序；只有任务明确允许规范化时才 trim、rstrip、压缩空白或补删分隔符。先区分源文本已有的终止符与任务要求额外插入的分隔，不能未经核对先删再拼。
- 在生成目标内容前，从原始任务要求建立独立的验收条件，覆盖相关的完整身份、位置、内容顺序与格式。保存后通过正常应用或任务允许的接口读回实际结果；不能只验证显示标题，或只比较“读回内容 == 自己构造的字符串”。后一比较可证明输入一致，但若构造逻辑本身漏了要求，仍不能证明任务完成。
- 分开报告创建成功、输入一致、保存后读回和任务验收通过。证据只支持其中一层时，不把它升级为全部完成；缺少完整名称或持久化内容证据时明确未验证部分，不凭 matches=True 宣告成功。
- 延续批量能力：定位、检查独立字段、构造、保存和读回可在一次 Python 调用内完成；在可编程验证的条件不符时停止依赖它的后续动作，并返回最小差异。只有名称语义、格式要求或观察需要模型判断时才返回模型，不要求每次输入都截图或往返。
- 不将上述检查变成 Runtime 自动改名、自动删后缀或自动修正文；不读取隐藏 reference/evaluator 来给执行 Agent 提供答案，也不写固定任务名、扩展名或空白行数量特例。

### 033 的证据与限制

原 exec13 的创建框有独立扩展名字段，默认 `.md`；成功 exec15 只修改名称，保留该默认值。三份源文本原本均带末尾 LF，exec15 主动 rstrip 后按单 LF 拼接；exec17 实际重开条目带 `.md`，正文只有三行、没有空白行。其 matches=True 仅比较省略后缀的标题和自己构造的 merged 字符串。因此本建议针对完整身份、源格式保留和独立验收条件，而不只重复“保存后再读一次”。

原实际判分要求精确无扩展名路径及段间空白行；离线实际纯函数/原源码表达式确认了相应失败机制，但原 find/cat 输入与首个返回 0 的分支未保留。不能宣称扩展名是唯一历史原因、空白行检查原次必然到达、当前 UI 无扩展名保存能力已经验证，或任务无解。任务措辞也有解释空间；本例不等同于 014 已证实的展示副本/reference 不一致。

证据：[033 父复核](033-MarkorMergeNotes/review.md)、[033 原始证据与所有者报告](../../markor-merge-diagnosis-20261109T090714Z/offline-report.md)、[033 本项独立离线验收](../../markor-merge-diagnosis-20261109T090714Z/independent-033-acceptance.md)。独立验收通过的是诊断，不是本建议的修复效果。正式技能实施后仍须按下文验证要求，在真实应用上执行独立 Agent 小样本及原成功样本回归；不默认启动全量评测。

## BrowserMaze 已有证据与限制

原 20 个 UI 动作中：10 个前置导航、6 个无迷宫进展的 element.click、4 个坐标 tap。第一个坐标 tap 有截图证明 X 右移；后续三个只证明请求返回，没有位置证据。六步计划路线根据原截图独立重算可达目标。

这支持“未经验证就批量依赖该交互会放大浪费”，不支持“批量本身有错”。也尚不证明 element.click 无效的底层原因。该任务目前需要视觉识别 X 位置，在没有可靠本地解析器时，检查点会增加模型往返；应承认这一成本，不能声称无性能损失。

## BrowserMultiply 的交叉检验

原记录的五次点击批量已有 WebDriverWait，但它只等待数字文本非空，返回 [9,9,9,9,9]；后续 page_source 却显示 10，按钮仍在。证明“加一个检查”不够，检查必须与本次进展相关。其后的四次点击批量仍只等数字；数字区隐藏、输入表单出现后，正常阶段切换被报为超时。Agent 随后没有读取该 cell 在持久命名空间中可能留下的部分列表，而是猜测乘积提交。

独立桌面浏览器运行当前仓库原 HTML 和相同 seed，按真实可见 UI 观察到初始数字、四次新数字和第五次进入表单；其中相邻两次有效点击可以产生相同数字。这支持上面的阶段分支、初始证据保留和重复值歧义规则，反驳“等待数值变化即可”的简单修补。诊断不访问隐藏 numbers/clickCount 来完成交互。

复现脚本在一次 Python Eval 中完成多步点击和观察，说明阶段检查不要求每步模型往返。但它不是 Android Appium 或 AMKernel Agent 重跑，没有证明原生点击失效原因或正式 skill 的收益。详见 `004-BrowserMultiply/review.md` 和 `desktop-page-semantics-smoke.json`。

## 040：答案提交契约与统计覆盖必须分层处理

### Harness：明确并一致执行答案字段类型

原任务要求只回答一个数字，但同一原提示末尾又要求返回带 taskOutcome、sessionCleanup、evidence 的 JSON 对象，未说明 taskOutcome 必须是字符串。Agent 返回数值字段 taskOutcome: 3；原结果直接记录 agentAnswer.validContract=false、sha256=null。保存的旧模板与原提示逐字匹配；对应保存源码的提取器只接收字符串，实际离线运行对原数值字段返回 None，仅将字段改为字符串 "3" 的受控候选才提取成功。裸数字也不能通过该包装提取器，因此不能简单指导模型忽略控制协议、只输出 3。

这首先是评测 Harness 的提示、解析与答案提交接口问题，不是 AMKernel Runtime 应自动修正的内容，也不能一律归为模型不遵守任务要求。新协议应明确 taskOutcome 的类型，使提示、解析、提交和无效结果诊断一致；是否支持 JSON number 须显式约定，不能由 skills 猜测、任意强转，或据此重算冻结成绩。当前模板已有明确字符串要求，不能将当前文字倒推为历史 Agent 已收到的指令，也不能把既有改动当作本次修复效果。

历史源码身份有局限：保存的 runner 能逐字还原原提示并匹配原模板 SHA，提取行为也与原无效答案记录一致，但保存源码整树不能冒称匹配原 campaign 的 harnessSource SHA。空答案缓存的评分早返须与实际记录区分，不把源码推导说成已观察的历史缓存内容，也不误述为“JSON 全文进入数值比较失败”。

### Skills：统计任务先证明范围与覆盖，失败检查不能被弱化

- 先确认统计范围和对象定义：目标容器、筛选状态以及任务要求计入的项目类型；不能仅凭全树出现目标名称就认定当前主视图与统计范围正确。
- 区分当前可见/已加载数量与全部数量。分页或虚拟列表需要覆盖证据、可靠总数来源，或有稳定身份依据的遍历与去重；不能按可能重复的标题任意去重，也不能只数第一页就宣称总量。
- 显式等待失败后，先只读诊断真实状态；恢复必须重新满足相关业务条件，不能把“抽屉已关闭且目标主视图稳定”的条件降格为“任意文本里出现目标名称”。抽屉节点仍在源码中也不单独证明错误容器或视觉遮挡，须结合布局与可见性证据判断。
- 范围、覆盖与计数可在同一 Python 调用内批量验证，返回 count、覆盖依据及未确认项；不要求每次滚动都返回模型。证据不足时不宣称总量已验证，不凭任务数字碰巧一致掩盖验证缺口。
- 将业务答案与控制层清理证据分离，遵循已明确的输出字段类型；协议未说明类型或互相冲突时，应记录接口缺口，不能把通用技能写成某个 benchmark 的 JSON 类型补丁。

原 exec9 已有 Ideas 顶部标题与三个待办控件；exec10 等待 Notebooks 消失失败，exec11 仍有 Notebooks，却仅以任意文本含 Ideas 和全树三个控件结束。这里存在可独立改进的状态/覆盖验收缺口，但不证明计数 3 错误，也不证明该缺口导致本项 0 分。两层建议均未在本次实施为正式技能或 Harness 修复，不能宣称收益已验证。

证据：[040 父复核](040-NotesTodoItemCount/review.md)、[040 原提示与答案路径来源证明](../../notes-todo-count-diagnosis-20261109T093949Z/owner-scorer-source-proof.json)、[父实际提取器离线验证](../../notes-todo-count-diagnosis-20261109T093949Z/parent-historical-extractor-smoke.json)。

## 051：去重必须确认内容等价，删除后保留每类至少一份

以下是删除与去重的通用技能候选，不是正式 skill 修改或收益验收：

- 先从任务明确“重复”的业务定义。相同标题、简介或列表摘要只能筛选候选，不能证明内容完全相同；应通过正常应用或任务允许的接口比较相关详情。不能用数据库 ID 不同否定内容重复，也不能用标题相同抹掉正文、材料、数量、时间等业务差异。
- 首次删除前，至少建立待删对象与保留对象的等价证据；只打开一个详情不构成两份等价。保留每个不同内容组的实例，而不是每个显示名称只留一份。
- 列表变化后，重新定位的“第一个同简介条目”不是此前已验证对象。后续破坏性动作必须绑定重新确认的对象内容和保留条件；身份不确定或发现字段差异时，停止删除依赖链，返回歧义而非继续清到只剩一个摘要。
- 删除后的检查同时覆盖目标冗余已去除、保留对象仍在以及不应改变的不同内容仍在。列表返回、确认框消失或 HTTP 成功只证明交互阶段；当前可见条目数可能因虚拟列表补位而不变，不能据此盲目再删。
- 已可靠建立等价组和身份时，可在一次 Python 调用中批量比较、删除和校验；不要把安全检查退化成每次点击都返回模型。需要解释内容差异或无法稳定识别对象时才返回模型，不为省预算省略删除前提。

### 051 的原证据与局限

原任务要求仅删除完全重复项并保留每种不同食谱。原参数共12行、11种完整业务内容；唯一重复组有两份。但执行中使用的同标题/简介筛选条件可匹配5行、4种不同内容。原 exec16 读取了一份详情，exec19确认一次删除；exec20–22按相同简介重新选取首个条目并继续确认删除，没有读取这些重新选中对象的详情并与保留对象比较。最终以两条可见标题、不同简介宣称完成。

父实际离线比较见 [参数等价性验证](051-RecipeDeleteDuplicateRecipes2/parent-parameter-equivalence-smoke.json)。它证明摘要选择条件不能区分应保留的不同内容，不是原前后数据库或新评分；四次成功删除确认也不单独证明四次持久化删除及具体被删 ID。不能仅凭原0分补造历史数据库状态或精确失败分支。本例的批量风险在于身份/等价前提缺失，不在于一次调用有多个动作。

## 052：保留对象与出现次数，错误后先核实，诚实失败不等于安全执行

本项补充051的去重意见，不把原Agent诚实报告失败改写成错误宣告完成。以下仍是通用修改候选，未实施为正式skill或现场验证：

- **扫描不能先把候选合并掉。** 摘要可以用来聚合搜索，但同标题、简介、来源的多次出现应保留为待核实候选，而不是先放入去重集合后丢掉次数。记录有界窗口及重叠、已覆盖范围和终止依据；既不能把跨窗口复现计为新记录，也不能把不同对象的相同摘要合为一条。固定次数滑动且不再观察末尾不能证明全量覆盖。
- **定位事实必须属于同一张卡片。** 从卡片共同祖先提取标题、简介、可见详情与当下定位依据；分别读取的标题和简介数组即使长度相等也不能默认按索引对应，长度不同更不能把第一标题当成第一简介对应对象。内容或位置不确定时先补充正常应用观察，不直接串接删除。
- **失败响应不是回滚。** 一个调用先确认删除、后读取属性报错时，应区分已执行前缀和失败观察。先核实业务状态，不因整次调用failed而重放破坏性动作。052的首次删除确认后才在父节点读取时抛错；随后只读核对页面的做法应保留，不能误称它盲目重复了同一次删除。
- **出现疑似误删或身份矛盾时，暂停后续破坏性动作。** 可用普通应用界面的可靠撤销入口时先核实并恢复；没有入口或没有原始完整内容时，不能凭记忆、模板或评测数据补造对象。恢复不确定就如实报告影响。寻找撤销未果后，不应仅因剩余条目摘要相同便继续删另一条。
- **把比较和保全检查放在动作之前。** 在剩余动作内优先建立完整等价对与保留副本，而不是先花预算删除方便找到的摘要重复项，最后才比较真正含大量变体的候选。证据不足时保留不确定对象并诚实失败；不调整预算，也不以“已发现错误、最终报告失败”视作安全要求已满足。
- **保留批量能力。** 同一Python调用可以批量获取结构化窗口、比较已知字段并执行有前置条件的动作；在身份冲突、不可逆动作前提失效或恢复不确定处停止依赖链并返回证据，而非强制每个点击都返回模型。已有JSON-native观察、真实控件类型、部分执行后核实指导继续复用，不增加工作流状态机或Runtime自动恢复。

### 通用指导候选

1. **目标身份以授权观察为准。** 相似图标、launcher快捷入口或搜索回显不是目标应用已打开的证据；核对实际包和页面。当前镜像上观察到的不可点击占位搜索行只能说明该次搜索未产生可用入口，不能推广成所有launcher搜索不可用，也不能把benchmark包名/固定坐标写成通用首动作。界面连续不变时停止重复同一路线；允许的其他入口须先有依据，不能假定存在。
2. **输入、提交和业务完成分开验收。** `send_keys`回显不等于日期选择器已提交、收件人已确认、消息已发送或文件已持久化。核对提交后的业务状态；未提交不要推进依赖动作。native EditText中的Selenium modifier私有字符可能被按文本发送，不能据一次HTTP成功推定Ctrl+C实现复制；核对当前context与真实控件语义，不新增全局快捷键转换或Runtime自动修复。
3. **完成成员资格不能只看可见性或checkbox外观。** 对已完成/未完成、类别、priority等条件，用实际可用且可信的筛选、详情或业务状态确认；菜单文字、accessibility `checked=false`或行仍在不能单独证明成员资格。切换前后记录同一对象/行集合及变化，必要时读回，不能把某一可用filter写成唯一入口或全app默认。
4. **聚合必须同时绑定范围、类别、字段与覆盖。** 日期边界、目标类别和聚合字段分别确认；可见窗口不等于全集，duration与moving/total字段不能随意替换。按稳定身份处理跨窗口重叠，保留不同对象的相同标题，不能盲目title去重。能在同一Python调用内完成有界读取、解析和计算时继续批量，缺失覆盖依据就报告限制。
